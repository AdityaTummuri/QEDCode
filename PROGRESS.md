## Known issues
- LICENSE in the repo is GPL-3.0 (created with the repo); the plan's step 8.4 suggests MIT or Apache-2.0. Left as GPL-3.0 for the human to decide.
- Ruff is told to skip `*.md` and `docs/` so AGENTS.md stays byte-identical to the brief.
- HelperConfig has an extra 'base_url' field (not in the brief's TOML) so an openai_compat helper has somewhere to point; the brief's make_client(role='helper') needs it.
- PyYAML added as a dependency: the brief requires YAML (catalog.yaml, FakeModel scripts) but its allowed-stack table does not list it. Human should add it to AGENTS.md section 2.
- Ranking differs from the brief's example: 9B=1, 4B=2, Coder-7B=3, 2B=4 so bigger cards get the best model that fits; the 4B stays the default in config and wins on 4-6 GB cards. Change rank in catalog.yaml if you prefer otherwise.
- llama.cpp 'releases/latest' is v1.0.0 with NO binaries now (builds live in b12xxx tags), and Linux CUDA builds DO exist now, unlike the brief. The installer pins DEFAULT_LLAMACPP_TAG=b12549 and Linux NVIDIA gets CUDA first, then Vulkan, then CPU. Asset names (win rocm instead of hip-radeon) were taken from the real b12549 release.
- Interpreter detection deviates from the brief on purpose: with a uv.lock and no .venv it does NOT run 'uv run python' (uv run creates a .venv inside the user's project, even with --no-sync). It falls back to python3/python on PATH and tells the user to run 'uv sync'.
- Design gap to handle in step 4.1: the project's interpreter is a path into the user's venv where the project may be installed in editable mode, so a worktree could import the user's code instead of the candidate. The pytest runner must put <worktree>/src and <worktree> first on PYTHONPATH.
- Decision: the cascade's apply stage lets protected paths through the applier (allow_protected=True) so the diff-based scope stage rejects them, as the plan's step 4.2 and scenario 3 say ('rejected at scope'); edits.apply still refuses protected paths by default for direct callers.
- Fix found by the plan's own 'Done when': a newly ADDED test file under tests/ no longer counts as a protected change (it would have capped grade A at B); only modified/deleted protected files and added config files count.
- Baseline selection now keeps only tests that exist at the base commit (a new test in the working tree made pytest exit 4 and the baseline 'not runnable').
- Controller deviates from the pseudocode in one way: a promising candidate gets the full suite immediately (not only after all tries), so stopping early means the proof is complete and a full-suite regression sends the loop on to the next try instead of ending with no fix.
- Fix found by tests: a repro test for a not-yet-existing function fails on the base as a collection error; the fail-before proof (cascade and verify) now treats a file-level failure as 'every test in that file failed before'.
- Found by the pilot tests: a Textual Static parses [Normal] as markup, hiding the current speed. All widget text now goes in as plain rich Text; my own helper must not be called _shutdown (it overrides Textual's).
- mcp 2.x renamed FastMCP to MCPServer (from mcp.server.mcpserver import MCPServer); the server uses the new name instead of pinning mcp<2.
