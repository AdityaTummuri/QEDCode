# QEDCode roadmap: summary

The living, editable version is the doc "QEDCode: Roadmap to a Masterpiece": https://claude.ai/artifact/YBa3rFDs7Zs3i8MZBW5zQw (created 2026-11-22). Edit that one; this page is a short snapshot for later chats in this project.

## Audit findings (2026-11-22)

- Strengths: engine of about 14k lines of source, 1,248 tests in the last full gate, CI on Linux/macOS/Windows with Python 3.11 and 3.12. Agent Skill v0.3.1: Antigravity reached grade A on 4 of 4 bug-zoo projects. Benchy: fair baseline-vs-QEDCode benchmark with Wilson intervals, McNemar tests, 143 SWE-bench Verified tasks without Docker, and results submitted by pull request.
- Gaps: no real-model numbers (PROGRESS.md says "NOT RUN"; the leaderboard is empty); README demo is still a placeholder; not on PyPI (404), and the QEDCode repo has no tag or release; the repo has no description, topics or website; GitHub Pages is off on all three repos; the Skill's v0.3.1 release is published on the Benchy repo by mistake; Benchy has uncommitted work (6 modified files plus assets/, docs/fresh-suites.md, tools/plant_bugs.py); the README test badge is stale (1,118 vs 1,248); the README is 31 KB; hardware pass step 8.3 is still open; docs/ has a .docx.

## Constraints

No servers, low maintenance, built with AI, free tiers only. Compute runs on the owner's GPU, the visitor's browser or the adopter's CI.

## Positioning

"The proof layer for AI-written code." qed check and qed verify need no model, so they serve cloud-agent users too. Keep "Small local models. Proven fixes." for the local door.

## Phases (suggested order)

0. Ship what exists: PyPI v0.2.0 through trusted publishing, a `qedcode` console-script alias so `uvx qedcode` works, a README first screen under 8 KB, screenshots and stats generated by CI, the .docx converted to Markdown.
1. Real-model numbers with Benchy on your own hardware, using local models rather than agent mode (the Antigravity quota ran out after 5-6 attempts). Runs: benchy-core plus the bug zoo, the 10-task swebench-verified-py pilot, and totals only for benchy-fresh. Headline metrics: resolution lift (Wilson CI, McNemar), grade honesty (the share of A grades that pass the hidden tests), silent failures, and the size jump (4B + QEDCode vs 9B alone).
2. `qed try` (a scripted demo that needs no GPU), a docs page that starts with `qed check`, a Codespaces devcontainer and a reproduce notebook.
3. A static site on GitHub Pages: a landing page, a Receipt Viewer that carries the receipt in the URL fragment (`qed receipt --link`), a "Fool the Grader" game in the browser (Pyodide + pytest), the Benchy dashboard, a replay gallery, docs and the case study.
4. A GitHub Action that runs `qed check` on PRs ("Catch AI pull requests that cheat their tests"), receipts signed with actions/attest, a pre-commit hook, the MCP Registry (mcp-name in the README, server.json, published from the release workflow), the Agensi listing and a Hugging Face dataset.
5. Engine work: mutation engine first (proof strength), then Safety Net Builder, Smart Questions, Bug Hunter, Night Shift and proof-carrying commits (git notes). Later, only if people ask: qed ui, Big Brain, Deep check, a WebGPU solve in the browser, the stop-or-continue judge.
6. The story: a study of test weakening in AI-authored PRs; the case study "Built by AI, proven by tests"; five posts; ADRs; a two-minute video; launch week, aimed at Tuesday 2027-01-12 after the holidays; resume lines.
7. Maintenance: Dependabot or Renovate, a weekly CI run against upgraded dependencies, a release pipeline started by one tag, and a 30-minute monthly routine in MAINTAINING.md.

## Not building

A hosted app, accounts or telemetry, a VS Code extension, Discord, new languages before anyone asks, a Benchy submission bot, chasing every agent's config format, LoRA training for now.
