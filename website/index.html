How a change is judged

        
Agents say “fixed”. QEDCode checks the evidence.

        
Every change walks the same ladder, cheapest check first. The first failure rejects it with the reason, and one function writes every grade from what actually ran.

        

          
AProven. A test failed before, passes now; the full suite shows no regressions; no test was touched.

          
BTested. The tests pass, but nothing proved the exact problem.

          
CChecked. It parses and lints, but no test covers it, or a test was weakened.

          
DNot checked. Nothing could run, and it says why.

Two ways in

      
Check what your agent wrote, or let a small model write it.

      

        

          
You use Claude Code, Cursor or Copilot

          
Let the agent make its change, then grade it. No model, no setup. In a pull request, the action posts the grade and blocks changes that weaken tests.


uvx qedcode check --fail-below B

# .github/workflows/qedcode.yml
- uses: AdityaTummuri/QEDCode@v0.2.0
  with:
    fail-below: B

          
Start here · The GitHub Action

        

        

          
You run small local models

          
A 4–9B model on a 4–6 GB card is wrong too often to trust once. QEDCode asks for several tries, tests each one in a throw-away copy, and keeps the one it can prove.


uv tool install qedcode
qed setup          # picks a model that fits your GPU
qed solve "fix the login bug"
qed apply          # only when you say so; qed undo reverses it

Receipts

        
Proof you can paste into a pull request.

        
Every result writes a receipt: the patch, every check that ran, what is not proven. qed receipt --link packs it into a link. The receipt rides after the #, which browsers never send to a server, so nothing is uploaded anywhere.
